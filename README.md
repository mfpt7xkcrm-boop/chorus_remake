# 合唱練習ノート

合唱祭に向けた練習の目標、録音、振り返り、次回の課題を端末内で管理する静的Webアプリです。ログインやサーバーは不要です。

## 主な機能

- 合唱祭までのカウントダウンと練習フェーズ
- 今日の重点目標（最大3件）
- 録音・再生・書き出し、録音の時刻付きコメント
- 音程・タイミング・発音・強弱・バランス・指揮・表現・統一感の5段階評価
- 総合評価と項目別評価の推移グラフ
- チェック式の課題、練習時間・内容・録音・評価を結ぶ練習記録
- 合唱情報（課題曲・自由曲・指揮者・伴奏者・パート構成・本番日）の任意設定

## ファイル構成

```text
.
├── dist/
│   ├── index.html       # GitHub Pages が公開するアプリ
│   ├── style.css        # 画面構成とレスポンシブ表示
│   └── app.js           # 画面、記録、録音、保存の機能
├── .github/workflows/
│   └── pages.yml        # main への push で dist を公開
├── .openai/hosting.json # 既存 Sites 公開先の設定
├── .gitignore
└── README.md
```

JavaScriptは既存データとの互換性を優先して単一ファイルを維持しています。画面関数、保存処理、録音処理、イベント処理を関数単位で分けています。録音の実データは `choir-audio-v1` の IndexedDB、その他の記録は `choir-practice-v1` の localStorage に保存します。既存のキーと録音IDを変更していないため、同じオリジンで更新すれば以前の記録を読み込めます。

## ローカルで開く

録音には安全なコンテキストが必要です。PCではこのリポジトリのルートで次を実行し、`http://localhost:8000/dist/` を開きます。

```sh
python3 -m http.server 8000
```

GitHub Pages は HTTPS です。iPad・iPhone では公開 URL から開いてください。`file://` で直接開く方法は録音確認に使わないでください。

## GitHub Pagesで公開する

1. GitHubで空のリポジトリを作成します。このフォルダをリポジトリとして `main` ブランチに push します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. **Actions** で `Deploy GitHub Pages` の完了を確認します。公開 URL は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
4. 更新後は `main` に push すると `dist/` が再公開されます。Actions が使えない場合は `dist/` の内容をリポジトリ直下に配置し、Pagesの公開元をそのブランチの `/ (root)` にします。

公開 URL が変わると、ブラウザの保存領域も別になります。以前の Sites URL の端末内記録は GitHub Pages に自動移行されません。移行が必要な場合は、元のURLを消さずに別途エクスポート機能を追加してください。コードのバックアップとブラウザ内の練習データは別物です。

## 対応予定ブラウザと動作確認

- iPad / iPhone: 最新の Safari
- PC: 最新の Chrome

録音前にマイクを許可してください。録音開始・停止、再生、書き出し、ページ更新後の再生とコメントジャンプ、録音・練習削除、横スクロールの有無を各端末で確認してください。実機検証の結果はまだありません。録音で失敗すると画面に処理段階、エラー名とメッセージを表示します。

## 既知の制限

- 記録はブラウザとサイトのオリジンごとに保存され、クラスとの共有・同期はありません。
- ブラウザのサイトデータ消去、プライベートブラウズ、容量不足で記録が消えたり保存できなくなる場合があります。大切な録音は端末に書き出してください。
- 録音中にページを閉じる、バックグラウンドへ移る、端末をロックする動作は保証されません。
- Safariの録音・再生は実機でまだ検証していません。MediaRecorderの対応形式は端末・OSのバージョンで変わります。
- 現在は音程の自動解析やAI採点を行いません。

## 今後の追加候補

まずデータ全体のエクスポート・インポートでURL変更時の移行とバックアップを可能にするのが適切です。その後、曲別の練習記録、パート別の振り返り、AI録音フィードバック、クラス共有・クラウド保存を検討できます。AIや共有には同意・アクセス制御とサーバー側の設計が必要です。
